高校联赛系统融合升级包（基于你上传的 sign_upweb-main.zip）
==================================================

本包是把账号/缴费/组队/比赛功能合并进现有 Cloudflare Pages + D1 项目的尝试版本，保留原有报名页、管理员后台和历史表数据。没有删除原来的表，也没有重建数据库。

本次改动
--------
1. 保留原有报名页、管理员后台、承诺书内容和原 API。
2. 新增选手账号注册/登录、角色选择、缴费订单登记、战队管理、我的比赛页面及相关 API。
3. 承诺书页面已去掉“选手参赛队伍”输入，不再要求填写队伍名称。
4. 承诺书新增“参赛意向身份”：队长（拟创建队伍）/队员（加入已有队伍）。旧记录保留，旧的 team_name 数据列继续留空兼容。
5. 首页增加账号/缴费、战队管理、我的比赛入口；原管理员后台增加新赛事管理入口。
6. 新增 migration 0006 和 0007；0007 只给承诺书记录增加 participant_role 列，不删除/覆盖已有数据。

部署前务必注意
--------------
- 先在 Cloudflare D1 做备份/导出。
- 确认 Pages 的 D1 绑定名仍为 LEAGUE_DB。
- 按顺序执行 migrations/0006_accounts_payments_teams_matches.sql 和 migrations/0007_commitment_participant_role.sql。你如果通过 Cloudflare SQL Console 操作，先检查 D1 的 migration 记录/表结构，避免重复执行 ALTER TABLE 0007。
- 将本包目录里的文件合并上传到现有 GitHub 仓库，保持 functions、public、migrations 目录结构；不要删掉原项目文件。
- 收款码图片需自行放在 public/wechat-pay-qr.png；本包没有真实收款码。
- 部署后先测试：原报名、原管理员登录/查看记录、承诺书提交、选手账号注册登录、缴费订单、队伍管理、管理员缴费审核、发布比赛。
- 账号与承诺书的“参赛意向身份”目前分别保存：承诺书选择会记录在承诺书提交中；用户账号页面的身份设置用于后续组队功能。两者尚未自动绑定为同一条账号记录。
- 这是 MVP 融合尝试包，尚未在你的 Cloudflare 真实 D1 环境做端到端测试。上线前应先用测试账号跑完整流程。发现报错时保留错误信息再修，不要清空数据库。
- admin-operations.html 是新增独立后台页面；请先登录原 admin.html，再点击“新增赛事管理”入口。
